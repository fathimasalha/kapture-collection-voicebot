# Kapture Finance Collections Voicebot - "Maya"

An automated outbound Collections Voice AI Agent designed to run compliant, low-latency collections conversations with overdue borrowers. Built with a state-enforced authentication gateway, bilingual capabilities (English/Hindi), and full CRM tool integration.

## 2. Design Choices & Pipeline Selection

To deliver a voice experience that feels responsive ($<1.2\text{s}$ latency) and matches the compliance standard of a financial institution, we selected the following core pipeline:

* **Orchestrator: Vapi.ai** — Coordinates SIP telephony, real-time audio streams, STT transcription, LLM orchestration, and speech generation out-of-the-box, saving development overhead.
* **Transcriber (STT): Deepgram Nova-2** — Optimised specifically for low-latency telephony audio. Provides real-time transcription streaming in $<200\text{ms}$ with high word-accuracy under noise.
* **Model (LLM): OpenAI GPT-4o-mini** — Configured with `temperature: 0.1` to maintain strict adherence to conversation states. GPT-4o-mini offers extremely fast time-to-first-token ($\sim 300\text{ms}$) compared to larger models, ensuring response latency stays minimal.
* **Voice (TTS): Cartesia (e.g., Sarah / Rachel)** — Selects an expressive, professional female voice. Cartesia's speech generation operates at $\sim 120\text{ms}$ latency with natural inflection, preventing the "robotic" pauses of older TTS systems.
* **Webhook Server: Express.js (Node.js)** — Written to process tool calls asynchronously and send structured JSON payloads back to Vapi under $200\text{ms}$.

## 3. Webhook Server Setup & Running Locally

The mock server simulates Kapture Finance's database backend to verify customer accounts, log Promise-to-Pay (PTP) commitments, trigger SMS payment notifications, and record call dispositions.

### Prerequisites
* [Node.js](https://nodejs.org/) (v18 or higher)
* [ngrok](https://ngrok.com/) (to expose the local mock server to Vapi.ai webhooks)

### Step 1: Install Dependencies
Navigate to the `mock-server` folder and install packages:
```bash
cd mock-server
npm install
```

### Step 2: Configure Environment
Copy the example environment file:
```bash
cp .env.example .env
```
*(By default, the server runs on port 3000)*

### Step 3: Run the Server
Start the server in development mode:
```bash
npm start
```
You should see:
```
======================================================
  Kapture Finance Mock Webhook Server is running!
  Port: 3000
  Endpoint: http://localhost:3000/webhook
======================================================
```

### Step 4: Expose Server with ngrok
To allow Vapi's servers to send tool calls to your local machine, open a new terminal window and run:
```bash
ngrok http 3000
```
Copy the forwarding HTTPS URL generated by ngrok (e.g., `https://xxxx-xx-xx-xx.ngrok-free.app`). Your webhook endpoint to use in Vapi will be:
`https://xxxx-xx-xx-xx.ngrok-free.app/webhook`

## 4. Vapi Assistant Configuration

Follow these steps to wire up Maya on Vapi.ai:

1. **Create Assistant**:
   * Log in to the [Vapi Dashboard](https://dashboard.vapi.ai/).
   * Click **Assistants** $\rightarrow$ **Create Assistant** $\rightarrow$ **Blank Template**.
   * Set **Transcriber** to `Deepgram` -> `nova-2` -> `en-US` (or multilingual).
   * Set **Model** to `gpt-4o-mini` with temperature `0.1`.
   * Paste the content of [`vapi/system_prompt.txt`](file:///c:/SALHA/kapture-collections-voicebot/vapi/system_prompt.txt) into the **System Prompt** field.
   * Set **Voice** to Cartesia (e.g. `Sarah` or `Rachel` - professional tone).
   * Set **First Message** to:
     `Hello, this is Maya calling from Kapture Finance. Am I speaking with Mr. Rahul Sharma?`

2. **Register Tools**:
   * Go to **Tools** in the Vapi dashboard.
   * Create the four functions listed in [`vapi/tool_definitions.json`](file:///c:/SALHA/kapture-collections-voicebot/vapi/tool_definitions.json):
     * `verify_customer`
     * `log_promise_to_pay`
     * `send_payment_link`
     * `mark_disposition`
     * `escalate_to_agent`
   * Set the **Server URL** for each tool to your ngrok URL:
     `https://xxxx-xx-xx-xx.ngrok-free.app/webhook`

3. **Verify Connection**:
   * Click **Web Call** on the top right of the assistant screen to place a live test call and speak with Maya. Observe the mock server console output to verify real-time API integrations.

## 5. What Broke & How We Debugged It

### Challenge 1: Premature Debt Disclosure
* **Symptom**: In early testing, when asked "What is this about?", the LLM would occasionally explain that the loan was overdue before running verification, breaching regulatory compliance.
* **Fix**: We enforced a strict prompt regime and state numbering system (STATE 0, STATE 1, STATE 2). The system prompt specifically warns that terms like "loan", "EMI", "overdue", and "₹8,499" are forbidden in STATE 0 & 1, and enforces that STATE 2 is unreachable without the success return of the `verify_customer` tool call.

### Challenge 2: Conversational Latency Spikes
* **Symptom**: Parallel tool execution for logging a PTP and sending payment links caused a delay in Maya's confirmation response, resulting in awkward silence.
* **Fix**: Modified the prompt sequence. Maya triggers `log_promise_to_pay` and `send_payment_link` in immediate succession, returning success indicators back as one turn, keeping E2E execution under `1.1` seconds. We also switched the model from standard `gpt-4o` to `gpt-4o-mini`, shaving off $\sim 200\text{ms}$ of LLM time.

### Challenge 3: Bilingual Code-Switching Context Loss
* **Symptom**: When switching from English to Hindi mid-conversation, the transcriber (STT) would occasionally output phonetic spelling (e.g. "haan", "parso"), causing the LLM to lose the exact date of payment or PAN verification digits.
* **Fix**: Configured Deepgram to handle English-Hindi multilingual mode and augmented the prompt with a Hinglish dictionary mapping (e.g., "parso" $\rightarrow$ day after tomorrow, "aaj" $\rightarrow$ today). We added explicit examples of Hindi state inputs in the system prompt rules.

## 6. Testing at Scale & Future Enhancements

With more time and budget, we would implement the following features:

1. **Automated LLM-as-a-Judge Evaluation**:
   * Set up a test runner script that runs simulated conversation transcripts against the test cases in [`tests/test_cases.json`](file:///c:/SALHA/kapture-collections-voicebot/tests/test_cases.json).
   * Evaluate prompt robustness using LLM judges to ensure that *zero debt words* are spoken before verification is complete.

2. **Dynamic Calling Hours Verification**:
   * Implement a hook in the webhook server that checks the customer's local time before Vapi answers or initiates an outbound trigger. If the local time is outside 8 AM - 7 PM, immediately terminate the call with a reschedule disposition to comply with RBI lending rules.

3. **SMS & WhatsApp API Integration**:
   * Connect actual [Twilio](https://www.twilio.com/) (SMS) or [Meta WhatsApp Business API](https://developers.facebook.com/docs/whatsapp/) SDKs to `send_payment_link` to send a live, trackable payment URL in real-time.
